# Реестр архитектурных решений

ADR документируют **почему** выбраны решения; реализацию/пути вызовов см. в главном `README.md`, `docs/api.md` и коде. Структура взята из предоставленного шаблона «Шаблон обоснования архитектурных решений»: контекст; решение; затронутые продукты; варианты; сравнение по MUST/SHOULD/COULD; положительные и отрицательные последствия. Статус «принято» означает фиксацию уже применённого проектного решения, а не отдельное формальное согласование.

1. [ADR-001 — Микросервисная архитектура](001-microservices.md)
2. [ADR-002 — Безопасность системы](002-security.md)
3. [ADR-003 — Распределённое бронирование (Saga)](003-distributed-booking.md)
4. [ADR-004 — Алгоритм распределения номеров](004-room-selection.md)
5. [ADR-005 — Отказоустойчивость](005-resilience.md)
6. [ADR-006 — Восстановление согласованности / Saga Recovery](006-saga-recovery.md) — расширение сверх минимального ТЗ

Когда проектное решение будет заменено, прежний ADR следует пометить «Устарело», а новое решение оформить отдельным ADR со взаимными ссылками, как рекомендует пользовательский шаблон.
