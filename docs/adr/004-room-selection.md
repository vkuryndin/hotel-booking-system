# ADR-004. Алгоритмы выбора номера и защита занятости

**Статус:** принято (реализовано в учебном проекте; описание на 31.10.2026).

## 1. Контекст

По ТЗ рекомендации должны быть на основе timesBooked по возрастанию с tie-break по ID. Нужно не путать операционный флаг available и занятость конкретного интервала.

**Основание:** ТЗ Skillfactory/МИФИ, требования к микросервисам, безопасности, алгоритму занятости и распределённой согласованности; реализация в исходниках Hotel Booking System.

## 2. Решение

Применён Strategy: `LeastBookedStrategy` сортирует по `timesBooked`, затем `id`; дополнительная `MostExpensiveStrategy` даёт выбор по стоимости. В Hotel Service доступность по датам вычисляется по резервированиям/ночам, а не по `available`. Стратегия настраивается на уровне отеля.

## 3. Подверженные решению продукты

Hotel Booking System — соответствующие компоненты: Booking Service и Hotel Service.

## 4. Рассмотренные варианты

**Вариант 1. Только флаг available.** Не учитывает даты и приводит к неверному запрету повторного использования номера.

**Вариант 2. LEAST_BOOKED + дата-слоты + Strategy.** Выполняет обязательную рекомендацию и даёт расширяемость.

**Вариант 3. Продвинутая ML/статистическая модель.** Сложнее, не требуется для учебной задачи.

## 5. Сравнение вариантов

| Критерий | Приоритет | Вариант 1 | Вариант 2 | Вариант 3 |
|---|---|---|---|---|
| Верная занятость по датам | MUST | Нет | Да | Возможно |
| Сортировка timesBooked/id | MUST | Нет | Да | Не гарантирует |
| Расширяемость стратегий | SHOULD | Низкая | Высокая | Высокая |
| Трудоёмкость | COULD | Низкая | Средняя | Высокая |

Приоритеты: **MUST** — обязательный; **SHOULD** — желательный; **COULD** — дополнительный. Оценки качественные, без вымышленных количественных измерений.

## 6. Последствия

Плюсы: предсказуемый подбор и детерминированность при равных счётчиках; возможность альтернатив без изменения API брони. Минусы: статистика `timesBooked` требует согласованности при отмене/компенсации, стратегии могут по-разному влиять на баланс нагрузки. Контроль параллельных слотов — часть доменной логики Hotel Service.
