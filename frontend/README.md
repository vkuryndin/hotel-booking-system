# Hotel Booking — React frontend (v6, 31.10.2026)

Полный frontend, основанный на v5. Backend не включён и не менялся.
API сверены с исходниками `hotel-booking-system(20261031-104523).zip`.

## Запуск (Windows / IntelliJ IDEA)

Распакуйте `frontend/` в корень `hotel-booking-system/` поверх старой версии.
Убедитесь, что Eureka, API Gateway, Hotel Service и Booking Service запущены.

```powershell
cd frontend
npm install
npm run dev
```

Откройте http://localhost:5173/. Сборка для проверки: `npm run build`.
Если IntelliJ уже содержит npm Run Configuration `Frontend`, её менять не требуется.

## Новое в v6

- `/admin/rooms`: кнопка «Добавить номер» открывает **мастер поверх каталога** в три шага:
  1. Данные: номер, категория, вместимость, цена и удобства из enum `RoomAmenity`.
  2. Фотографии номера: JPEG/PNG/WebP до 5 МБ, максимум 10; главное фото, сортировка и удаление.
  3. Проверка: сводка с главной фотографией и кнопкой «Создать ещё номер».
- Запрос `POST /api/rooms` выполняется один раз при первом переходе к фотографиям. Возврат к данным обновляет **тот же номер**, не создаёт дубликат. Закрытие мастера после POST не удаляет уже созданный номер.
- `/admin/rooms`: исправлено редактирование: номер через `PUT /api/rooms/{id}` `{number}`, категория/цена/вместимость/удобства через `PATCH /api/rooms/{id}/details`.
- `/admin/hotels`: название и адрес существующего отеля теперь редактируются через подтверждённый `PUT /api/hotels/{id}` `{name,address}`; оформление отдельно через PATCH.
- Фотографии номеров: маршрут `/api/rooms/{roomId}/photos` (список, загрузка, чтение, primary, sortOrder, удаление) **проверен в RoomPhotoController**. Порядок фотографий сохраняется явной последовательной переиндексацией, исключающей ничем не гарантированную сортировку при совпадении sortOrder.
- В форме создания отеля проверяются максимумы DTO: название 150 символов, адрес 255, описание 3000. В формах номеров номер до 20 символов.

## Сохранено из v5 и предыдущих обсуждений

- Мастер отеля поверх ADMIN-каталога: Основное → Оформление (включая стратегию) → Фото → Номера и их фотографии → Проверка.
- `LEAST_BOOKED` или `MOST_EXPENSIVE` задаёт **ADMIN отдельно для каждого отеля** (GET/PUT `/api/hotels/{id}/room-selection-strategy`). Пользователь стратегию не выбирает. При авто-подборе frontend **не отправляет** параметр `strategy`; backend использует настройку отеля.
- Страница отеля и номера: пользовательская фотогалерея и полноэкранный просмотр.
- История бронирований и оформление: фото номера, при отсутствии — фото отеля.
- Читабельные шрифты, аккуратные галочки, расположение кнопок галереи, исправление регистрации `.auth-panel > .eyebrow { display:block; margin-bottom:12px; }`.
- Удобства строго по Java enum: Hotel `WIFI/PARKING/POOL/GYM/RESTAURANT`; Room `WIFI/TV/AIR_CONDITIONING/MINIBAR/BALCONY`.
- JWT, Vite proxy на `localhost:8080`, `Idempotency-Key`, роли USER/ADMIN, история и отмена бронирований, кабинет, статистика.

## Особенности API

Отель создаётся через `POST /api/hotels {name,address}`; фотографии и номера доступны **после** получения ID. Backend не предоставляет единого атомарного создания отеля с комнатами и фотографиями: если закрыть мастер после POST, объект остаётся в базе. Это явно указано в интерфейсе.

Для фотографий в браузере выполняется JWT-аутентифицированный запрос, затем показывается Blob URL. При отсутствии фото видна заглушка. Онлайн-оплата не выполняется.

**Сборка в среде подготовки:** синтаксис JS/JSX и относительные импорты проверены. `npm install` недоступен из-за отсутствия пакетов в локальном cache и доступа к registry, поэтому Vite-сборка и интеграционные запросы к живому backend не запускались. Проверьте `npm install && npm run build` у себя.
